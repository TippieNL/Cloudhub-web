# Cloud File Hub — FFmpeg on Android/KSWEB

Cloud File Hub does not require an FFmpeg PHP extension. Video thumbnails are generated by launching the `ffmpeg` and `ffprobe` command-line programs from PHP.

KSWEB bundles PHP, web servers, MySQL/MariaDB, FTP and related tooling, but FFmpeg is not listed as one of its bundled components. Therefore FFmpeg must be supplied separately. KSWEB serves projects from its `htdocs` storage and supports PHP 8.x. See the KSWEB product information for the current bundled stack.

## 1. Copy the project

Extract Cloud File Hub into the KSWEB `htdocs` directory.

The project should contain:

```text
Cloud File Hub/
├── bin/
│   ├── ffmpeg
│   └── ffprobe
├── public/
├── src/
├── storage/
└── ...
```

Do **not** put FFmpeg under `public/`.

## 2. Supply Android binaries

The binaries must be native Android command-line executables for the phone architecture. For a typical modern Android phone this is `arm64-v8a` / `aarch64`.

A desktop Linux ARM64 binary is not automatically an Android binary. Likewise, Windows `ffmpeg.exe` cannot run on Android.

You need both:

- `ffmpeg`
- `ffprobe`

and both must be executable by the PHP process used by KSWEB.

## 3. Start with automatic discovery

The included `.env.example` uses:

```dotenv
FFMPEG_PATH=auto
FFPROBE_PATH=auto
```

With `auto`, Cloud File Hub checks its own `bin/` directory first and then falls back to the process PATH.

## 4. Android shared-storage caveat

If the project is under a path such as:

```text
/storage/emulated/0/htdocs/Cloud File Hub/
```

Android filesystem/SELinux policy may allow PHP to read the executable but refuse to execute it from shared storage. This is an Android execution restriction, not a Cloud File Hub bug.

If that happens, put the binaries in a KSWEB-accessible executable directory and set absolute paths:

```dotenv
FFMPEG_PATH=/absolute/path/to/ffmpeg
FFPROBE_PATH=/absolute/path/to/ffprobe
```

Do not guess this path. Use the diagnostic output below to determine what PHP can actually execute.

## 5. Run diagnostics

From PHP CLI, run:

```text
php tools/ffmpeg-check.php
```

If your KSWEB installation does not expose PHP CLI directly, the application also provides an authenticated admin endpoint:

```text
GET /api/system/ffmpeg
```

The endpoint reports whether PHP can execute FFmpeg/FFprobe and whether the thumbnail cache is writable. It does not expose arbitrary command execution.

## 6. Test a video

After the diagnostics report:

```text
Ready: YES
FFMPEG Available: YES
FFPROBE Available: YES
```

open the Cloud File Hub gallery and load a video. The first request generates the thumbnail; subsequent requests use the cached WebP file.

## 7. Thumbnail cache

Generated thumbnails are stored at:

```text
storage/.thumbnails/videos/
```

The cache key contains the video path and modification time. Replacing or modifying a video therefore causes a new thumbnail to be generated automatically.

## 8. Security

Keep FFmpeg outside `public/`. Never accept an executable path from an HTTP request. The application only reads the configured server-side environment value and known application paths.
